# `code/` 研究阶段代码总览

---

## 0. 先看这三句话

1. `code/` 里多数脚本是**单文件实验脚本**，不是统一工程。
2. 复现时不要随机运行，先按本文的 **Pipeline A（最短链路）**。
3. 几乎所有脚本的 `E:\...` 绝对路径都要先改成本机实际路径。

---

## 1. 你现在有两条主线

### 主线 A：分割/跟踪/规则判定（球和人）

```text
原视频 + SAM输出
   └─ use_sam3.py / use_sam3_彩色.py   (生成提取视频)
      └─ sam3数据结构拆分.py            (输出目标坐标 CSV)
         └─ 优化对羽毛球落地判定.py / 1.23完整版final.py
```

### 主线 B：姿态/生物力学/LLM复盘（人）

```text
原视频
   └─ start_analysis.py 或 Sports2D外部输出TRC
      └─ 数据提取.py                    (输出生物力学特征 CSV)
         └─ api调用qwen.py              (输出文本复盘报告)
```

> 两条主线可以并行：A 负责球与时序事件，B 负责人体动作质量。

## 3. Pipeline A（最短可复现链路，建议先跑）

> 目标：快速得到“可解释的复盘结果”。

1. 准备原视频 `final.mp4` 与 SAM 输出视频（同帧率/时长尽量一致）。
2. 运行 `use_sam3_彩色.py`（更直观）或 `use_sam3.py`（更纯净）。
3. 运行 `sam3数据结构拆分.py`，确认坐标 CSV 有连续帧数据。
4. 同时跑姿态链路：`start_analysis.py` 或外部 Sports2D 产出 TRC。
5. 运行 `数据提取.py` 生成生物力学 CSV。
6. 运行 `api调用qwen.py` 生成复盘报告。

## 4. 复现前必改项（90% 报错来自这里）

- 所有 `E:\badminton\...` 绝对路径。
- 视频编码/帧率不一致导致的帧对齐问题。
- OpenCV GUI（`cv2.imshow`）在无桌面环境不可用。
- `rtmlib`/`openai`/`scipy` 依赖未安装。
- `api调用qwen.py` 中 API Key 为空。
